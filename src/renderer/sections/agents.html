The CLI this agent's work runs on. Its own model is used unless you override it below.

A task is a binding: an existing task or skill, plus a schedule.

A session is you driving a loop. An agent is that same machinery running without you — on a schedule, with a standing brief, reporting what it did.

The brief every run opens with, before the task's own program. Write it like you'd brief a person on their first day: what the job is, what "done" looks like, what to leave alone.

The loop is the CLI that does the work — it brings its own command, folder and tools. The model is optional: leave it on the loop's own unless this agent needs something different. The list narrows to what the chosen loop can actually address.

What it may reach for. Skills are instruction packs from the Skills page; apps are the slugs it's allowed to drive. Both are permissions, not instructions — naming one here doesn't make the agent use it.

Each task binds something that already exists — a task or a skill — to a schedule. They fire on the agent's loop with its prompt in front. Tasks only run while the agent is Live; pausing it parks every one without losing the schedule.

Ceilings for unattended work, so a loop that misbehaves at 3am can't run all night. Blank means no cap.

The detail view is where you operate it: pause it, toggle a task, change a schedule, run one now, and read the output of every firing.
