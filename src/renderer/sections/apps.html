How apps use config vars

                    

                      Config vars are per-app secrets: the key is visible below, the value is
                      encrypted on this machine before it's stored and can never be
                      viewed again — not here, not by the server. Delete and re-add a var to rotate it.
                    

                    

                      Credential vars are host-only. Any var whose name ends in
                      _API_KEY / _KEY / _SECRET / _TOKEN /
                      _PASSWORD is encrypted at rest and can never be read by app code —
                      secrets.get refuses it. Only the trusted Glyphh runtime decrypts and uses it,
                      returning results, never the value. That's what makes it safe to lend a model over MCP.
                    

                    

                      agent.run and llm.complete pick keys up automatically: a var named
                      ANTHROPIC_API_KEY / OPENAI_API_KEY / GOOGLE_API_KEY
                      powers that provider with no code at all. Non-credential config vars (a base URL, a
                      setting) are still readable via secrets.get. Keys belong to the app — Glyphh
                      has no key store and makes no model calls of its own.

What this app needs

                    

                      A Glyphh app is deterministic because it calls your connected accounts —
                      Gmail, Slack, a CRM — through Glyphh's governed connectors, never with its own keys.
                      Each connection it requires is listed on the left with whether you have it connected.
                    

                    

                      Expand a connection to see the tools the app depends on. A connection can be
                      connected but still have tools your org or workspace hasn't allowed — those show as
                      blocked, and the app can't call them until they're permitted on the
                      Connections page.

Exposing tools over MCP

                    

                      Any agent — your own Claude, or someone else's — can add this app's
                      /mcp URL as a connector and call the tools you approve. Everything
                      runs on your machine, sandboxed by the Glyphh runtime; the app must
                      be running (and your Glyphh client online) for calls to succeed.
                    

                    

                      Approval is an allowlist: a tool is unreachable until you switch it on, and any
                      newly-appeared tool stays off until you approve it. Every call spends credits and
                      is capped by the Guardrails limits.
                    

                  

                


                
                

                  

                    
Hard limits

                    

                      These caps are enforced at the gateway before a call reaches your machine, so a
                      runaway or abusive caller can't drain your credits or hammer your model. They apply to
                      every app that exposes an MCP endpoint.
                    

                    

                      Per-call caps bound a single request; the window caps (tokens / calls) reset every
                      window seconds; concurrency bounds simultaneous in-flight calls. Leave a field
                      blank to impose no limit there.
