Getting started

Glyphh is a workspace you configure for your way of working: an agent, your everyday web apps, an office suite, and the tools to build and publish your own — on desktop, web, and mobile.

Sign in

Signing in opens your browser at platform.glyphh.ai — approve the device code shown in the app (Google, Apple, or email). Your session is stored locally under ~/.glyphh and follows you into the CLI too.

Your workspace comes furnished

A new account starts with the apps most people already live in — Gmail, Calendar, Drive, Docs, Sheets, Slack, GitHub, Notion, the AI chats, and more — plus starter workspaces you can rename, delete, or rearrange.

First prompt

Pick a working folder (the agent header) and just ask. The agent reads and writes files there, runs commands, and streams every step as a receipt you can expand. New here? Start in ask mode — every action waits for your approval.

Two shortcuts worth learning on day one

⌘⇧SpaceFrom anywhere on your system — front Glyphh and open the command center
⌘⇧GAttach the agent to the app in front (desktop) — it rides its bottom edge, just like over a panel
.dip <name>In the composer — open any panel, app, or workspace by name

The other surfaces

platform.glyphh.ai runs the same workspace in your browser (the Desktop tab), and on a phone it becomes the mobile app — same sessions, same account. See Sessions & devices.

The command center

The wall is home: every app, workspace, and tool as an icon. Click to open; what you open covers the wall, and the wall is one keystroke away the whole time.

The wall

  • Pages — icons flow across pages; swipe or use the edge arrows.
  • Arrange — drag icons to reorder; press-and-hold for edit mode (the wiggle). Order is saved to your account, not the machine.
  • Folders — drag one icon onto another wall group to file it; an empty folder deletes with the standard confirm.
  • Multi-select — ⇧/⌘-click icons to move several at once.

The dock

The row at the top: New session, Apps, Marketplace, Connections, Workspaces, Scheduled Tasks, Agents, Loops, Skills, Browser, Settings, Sign out — plus Command center and Close all, which light up while anything is open. Drag dock and wall icons between the two rows to trade slots; the magnification arc and hover tick are yours to tune in Settings → Appearance.

Auto-hide

Settings → Appearance → Auto-hide dock tucks the dock off the top while panels are open; a sliver marks where it hides, and hovering the top edge peeks it back over everything. With auto-hide off, the top of the page reserves the dock's space instead.

Getting back to the wall

⌃⌥ (hold)Show the wall over open panels; release drops back
.dip backFrom any composer

The Glyphh Agent

The same engine as the CLI: real local tools (files, shell, web), streamed answers, and tool receipts you can audit. + starts a fresh session; recents live in the rail and the header dropdown.

Permission modes

The mode chip in the composer controls how far the agent goes without you (Shift+Tab cycles it):

askEvery write, edit, and shell command waits for approval (default)
autoReads run free; the agent acts, and you watch the receipts
planNo tools run — the agent outlines what it would do
read-onlyReads only; nothing on disk changes

Talking while it works

Type during a run and Enter queues your message as a note on the card — it sends as the next turn when the run ends. The note's × takes it back; its Interrupt button stops the agent now, so it reads what's waiting and continues. Stopping by hand with notes queued does the same thing.

Context

The context meter shows how full the model's window is and where compaction kicks in. The agent folds older turns automatically; click the meter — or type .compact [focus] — to fold now, optionally steering what the summary must keep.

Working folder

Sessions inherit the last working folder; the file tree, terminal, diff, and editor are all rooted there. The header's source chip can also point a session at a GitHub repo (cloned for you — see GitHub) or a cloud workspace (see Sessions & devices).

The attached agent (desktop)

⌘⇧G attaches the agent to the bottom edge of whatever app is in front — the same composer, tuck, hover-reveal, and lock it has over Echo's own panels, following the app's window as it moves. Your mouse works the app as normal; only the agent's own pixels take clicks. It steps aside whenever Glyphh itself is the front app, and ⌘⇧G again dismisses it.

Voice

Settings → Voice enables the composer mic: click to record, click to stop — transcribed into the composer. The agent can speak replies aloud, and hands-free mode hands the mic back after each answer. Esc (or the Stop chip) cuts a spoken reply short.

Sessions & devices

A session belongs to your account, not a machine. Start it anywhere; open it anywhere else and watch the live turn stream in.

Where a session runs

  • This machine — the desktop runs the agent locally in your working folder.
  • Cloud — the session runs in its own cloud workspace with a persistent filesystem; bind it to a GitHub repo and the repo is cloned there before the first turn.
  • A connected desktop — from mobile or web, pick one of your desktops and a folder on it; the turn runs on that machine.

The choice is fixed when the session starts — a session never silently moves between machines.

Following along

Open a running session from another surface and you see the live turn, tool receipts included. Desktop panels (Files, Diff, Editor) can follow a cloud session too, browsing its cloud filesystem in place.

Security model

Your desktop holds an outbound connection to the cloud. Nothing dials into your machine — mobile and web reach a desktop only through that link, and only for your own account.

Mobile

On a phone, platform.glyphh.ai is the mobile app (add it to your home screen): sessions, voice, connections, and the same working-folder choices — cloud, a GitHub repo, or a folder on a connected desktop.

Models

The model picker (composer chip) shows every model your org allows — frontier and open-weight in one list, priced per token in credits. The loop decides how many model slots you're picking for.

The catalog

Anthropic (Fable, Opus, Sonnet, Haiku), OpenAI (GPT-5.x), Google (Gemini), xAI (Grok), Mistral, DeepSeek, and hosted open-weight models. Admins govern which models an org and workspace can use; usage is attributed per model in your usage feed.

On-device models — zero credits

Models under On-device (Qwen2.5 1.5B–14B) run on your machine: picked like any other model, but the turn never leaves your computer and costs 0 credits. First use downloads the weights (one-time, size-dependent) and starts a local server. Requires llama-server — brew install llama.cpp — or point GLYPHH_LLAMA_BIN at a binary. Best as a loop's worker; keep a frontier model as the planner.

Bring your own key

Org admins can add a provider API key on the platform (Workspace → Connections → provider). With a key set, that provider's calls use it directly; without one, calls ride the Glyphh gateway and meter as credits.

Loops & automation

A loop is the agent's pipeline: named roles (planner, worker, …), the model bound to each, and the deterministic program that runs them. The same prompt behaves differently under different loops — that's the point.

Loops

  • Switch loops from the composer's loop chip; each role's model is picked in the same sheet.
  • Browse and edit loops on the Loops page (dock or rail).
  • A workspace can carry a loop and its model bindings — opening "Dev" can also mean "plan with Fable, work with a local model".
  • Loops follow RotorSpec, the open standard for deterministic agent loops; rrotor is the reference runtime.

Scheduled tasks

The Scheduled Tasks page is your standing work in one place: every task, when it fires next, how the last run went, and each task's full run history.

Loops

A loop (Loops page) is a pre-wired CLI: which one to run (Claude, Codex, Gemini…), its starting model, its working folder, and whether Glyphh's tools are connected to it. The CLI is the loop — Glyphh drives it rather than reimplementing it. Opening a loop plays that config into a terminal; the agent panel's chat view is the same loop, rendered differently.

Agents

An agent (Agents page) is a standing worker: a name, a loop, and the scheduled tasks it fires. Where a session is you driving, an agent is the same machinery running without you.

Skills

A skill (Skills page) packages instructions the agent loads for a particular kind of task — a manifest, a prompt, and optionally a program. Org admins can publish skills for the whole team.

Drips

Drips are full-screen effects — .drip <name> plays one (bare .drip is fireworks). ⌘⇧. kills every playing effect from anywhere, even when an overlay covers the screen.

Credits & billing

One prepaid currency for everything: model calls, tools, compute. Every charge is itemized per call in your usage feed — never billed in arrears.

How a turn is priced

  • Tokens — each model has an input and output rate in credits per million tokens (shown in the picker's info tip).
  • Prompt cache — cached input bills at a fraction of the input rate (reads 10%, writes 125%), matching what providers charge.
  • On-device models — 0 credits, always.
  • Compute (hosted runs) — metered by wall-clock time.

Plans & top-ups

Free starts you with 100 credits. Paid tiers add monthly credits, seats, connected services, and cloud sync. Top up without leaving the app (the credits modal), or manage billing, invoices, and the live usage feed at platform.glyphh.ai.

Stretching credits

Point your loop's worker role at an on-device or open-weight model and save the frontier model for planning — most of an agent session's tokens are worker traffic.

Panels & tools

Everything opens as a panel beside the agent. Drag headers to rearrange, drag edges to resize; arrangements are remembered per working folder, and named workspaces remember exactly how you left them.

Dev tools

  • Files — the working folder's tree. The search box searches the whole folder, not just what's expanded.
  • Editor — a Monaco editor over the tree's files.
  • Terminal — a real shell in the working folder.
  • Diff — what changed, as the agent works.
  • Browser — tabs, an address bar, and right-click to save any page as an app.
  • Plan — the agent's plan files, live.
  • Releases — release management for your built apps.

The office suite

  • Slides, Docs, Sheets — decks, documents, and workbooks the agent can write with you.
  • Drive — folders and pointers over every office file.
  • Design — design documents and assets.
  • Image / Video / Sounds — generated media, one panel, three views.
  • Band — songs, artists, and music videos.
  • Memory — the agent's memory, visualized.

Panels remember their document

Close a workspace with a deck open in Slides and an image open in Image, and reopening it brings back that deck and that image — every panel reopens on what it had open. Terminals restart (a shell can't be frozen), and Settings always opens at its front page.

Workspaces

A workspace is a saved arrangement — which tools and apps, in what grid — restorable in one click from the wall, the Workspaces page, or .dip <name>.

What a workspace can carry

  • Panels + tools — any mix of apps, dev tools, office panels, and Glyphh (the agent).
  • App setup per panel — the Browser cell opens at a URL you set; the Terminal cell runs a first command. Set both in the workspace editor’s App setup section.
  • A working folder — opening the workspace switches the agent to it.
  • Session behavior — keep the current session, start fresh, or resume this workspace’s own last session.
  • A loop + its models — opening the workspace activates that loop with those model bindings.

Your changes stick

Rearrange or resize inside an open workspace and it remembers — reopening brings back exactly what you left, open documents included, not the original definition. Starting a new agent session never resets an open workspace.

Apps

Apps live on the wall and the Apps page. Three kinds: web (any URL, opens as a live panel), native (launches a local application; desktop only), and glyphh (apps built on the Glyphh runtime — see Build & publish).

Adding your own

Apps page → + New: a slug, a name, and a URL (or a native app path). Org-visible by default so your team gets it too. Or right-click any page in the Browser panel and save it as an app.

Live panels

App panels are live — signed-in sessions, notifications, everything — and the agent can read from and act through them. Dot-commands typed in any panel drive the workspace without leaving the keyboard; see Commands.

Marketplace

The Marketplace lists published Glyphh apps — public and your org's own. Installs auto-update by default; pin a version from the app's Releases tab.

Commands

Dot-commands work from the agent composer and from any input in any app panel — the text is intercepted before the app sees it, so nothing leaks into the page. They work mid-run too.

.dip — navigate

.dip <panel|app|workspace|url>Open it — tool names (files, terminal, browser, slides, sheets…) resolve first, then workspaces, then apps, then URLs
.dip split <a> <b> …Open each, side by side
.dip grid <a> <b> …Open each, then even grid
.dip add <url>Open a URL as a panel
.dip close <name>Close one panel
.dip clearClose every panel
.dip listWhat’s open, and the workspaces that exist
.dip refreshReload the panel on top
.dip backBack to the command center

Build & publish apps

Glyphh apps are Vite static projects with a glyphh.app.json manifest, built by the agent (or you) in the working folder. The runtime gives them SQLite, on-device vector search, a knowledge graph, cron, your connections, and models — inside a strict sandbox (no external scripts; everything bundles).

The loop

ask the agent"Build me an app that…" — it scaffolds, builds, and installs locally
update_appThe agent reinstalls the working folder's build into your workspace
deployCut a release, upload the source, go live at <slug>.glyphh.app

Releases

The app's Releases tab is the lifecycle: Build & deploy packages the working folder's compiled build, cuts a release, uploads, and deploys; write notes; Promote to live is what installers get. Rolling back is promoting an older release again.

Listing

The Listing tab publishes to the Marketplace: description, media, required connections. Public or org-only.

Connections

Connections give the agent (and your Glyphh apps) authenticated reach into 3,500+ services — Gmail, Slack, Notion, Sheets, calendars, CRMs, and the rest.

Two kinds

  • Org connectors — shared by an admin; members use them without doing their own auth. Governed per workspace, down to individual tools.
  • Personal connections — your own accounts, connected by you, usable only by you.

Manage both under Workspace → Connections on the platform, or from the Connections page here.

Custom MCP connections

Point a connection at any remote MCP server URL — OAuth or headers — and its tools join the agent's toolkit. Custom MCP executes server-side under your org's governance; nothing runs on or dials into your machine.

GitHub

Link GitHub once and every surface can put the agent inside a repo.

Connect

The agent header's source chip (or the mobile Working-folder sheet) offers Connect GitHub — approve the GitHub App and pick which repos it covers. Disconnect any time from the same place.

What it unlocks

  • Desktop — clone a repo into an empty local folder straight from the source chip ("create from git"). Private repos clone with a short-lived, repo-scoped token that is never written to the remote or the logs.
  • Cloud sessions — bind a session to a repo and its cloud workspace has it cloned before the first turn; "clone the repo" is never a step you type.
  • Mobile — pick any covered repo as a new session's working folder.

Security

Clone tokens are minted per repo, expire in minutes, and are injected server-side for cloud runs — the client never holds long-lived Git credentials.

The CLI

The whole agent, in your terminal — the same engine, loops, models, permission modes, and metering as Desktop.

npm i -g @glyphh-ai/cli
glyphh

Good to know

  • Sign-in is the same device flow, and the session is shared with Desktop (~/.glyphh) — sign in once.
  • /login, /status, /loop, /theme, /help in-session; Shift+Tab cycles the permission mode.
  • Headless and scriptable — drop it in CI, cron, or a Makefile.
  • Install it on a remote box and that machine becomes reachable from your other Glyphh surfaces (machine-reach).

MCP

Glyphh speaks MCP in both directions.

As a client

Add remote MCP servers as custom connections (see Connections) — their tools join the agent's toolkit, executed server-side under org governance.

As a server — drive Glyphh from other tools

External tools (Claude, Cursor, anything MCP-capable) can connect to your workspace at:

https://api.glyphh.ai/mcp

In Claude, add it under Connectors and approve the OAuth prompt. Clients without OAuth use a token via mcp-remote:

{
  "mcpServers": {
    "glyphh": {
      "command": "npx",
      "args": ["-y", "mcp-remote", "https://api.glyphh.ai/mcp",
               "--header", "Authorization: Bearer YOUR_TOKEN"]
    }
  }
}

Connected tools can open your apps and workspaces, run your installed apps' tools, call your connections, and build + deploy Glyphh apps. Security model: your desktop holds an outbound connection to the cloud — nothing ever dials into your machine, and only clients you approve get through.
