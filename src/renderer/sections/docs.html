Getting started

Glyphh Desktop is an AI workspace: a coding agent, your everyday web apps, and the tools to build and publish your own — in one window.

Sign in

Signing in opens your browser at platform.glyphh.ai — approve the device code shown in the app (Google, Apple, or email). Your session is stored locally under ~/.glyphh and follows you into the CLI too.

Your workspace comes furnished

A new account starts with the apps most people already live in — Gmail, Calendar, Drive, Docs, Sheets, Slack, GitHub, Notion, the AI chats, and more — plus two starter layouts:

  • Email — Gmail on the left, Calendar on the right
  • Dev — Files and Diff on the left, Editor over Terminal in the center, the Coding Agent on the right

Everything is yours to rename, delete, or rearrange.

First prompt

Pick a working folder (the agent header) and just ask. The agent reads and writes files there, runs commands, and streams every step as a receipt you can expand. New here? Start in ask mode — every action waits for your approval.

Two shortcuts worth learning on day one

⌘⇧GGhost Mode — summon the agent over whatever app you're in
@an-fable fix thisAn @-mention in any input opens a fresh session on that model

The Glyphh Agent

The same engine as the CLI: real local tools (files, shell, web), streamed answers, and tool receipts you can audit. Sessions live in the left history; + starts a fresh one.

Permission modes

The mode chip in the composer controls how far the agent goes without you:

askEvery write, edit, and shell command waits for approval (default)
autoReads run free; the agent acts, and you watch the receipts
planNo tools run — the agent outlines what it would do
read-onlyReads only; nothing on disk changes

Loops

A loop is the agent's program: its roles (planner, worker, …) and the model bound to each. Switch loops from the loop chip; edit them (or build new ones) on the platform's Loops page. Layouts can carry a loop, so opening "Dev" can also mean "plan with Fable, work with a local model".

Context

The context meter shows how full the model's window is and where compaction kicks in. The agent folds older turns automatically; your working-folder choice, plans, and receipts survive it.

Working folder

Sessions inherit the last working folder. The workbench's file tree, terminal, diff, and editor are all rooted there, and saved arrangements are remembered per folder.

Models

The model picker (composer chip) shows every model your org allows — frontier and open-weight in one list, priced per token in credits. The loop decides how many model slots you're picking for.

The catalog

Anthropic (Fable, Opus, Sonnet, Haiku), OpenAI (GPT-5.x), Google (Gemini), xAI (Grok), Mistral, DeepSeek, and hosted open-weight models. Admins govern which models an org and workspace can use; usage is attributed per model in your usage feed.

On-device models — zero credits

Models under On-device (Qwen2.5 1.5B–14B) run on your machine: picked like any other model, but the turn never leaves your computer and costs 0 credits. First use downloads the weights (one-time, size-dependent) and starts a local server. Requires llama-server — brew install llama.cpp — or point GLYPHH_LLAMA_BIN at a binary. Best as a loop's worker; keep a frontier model as the planner.

Bring your own key

Org admins can add a provider API key on the platform (Workspace → Connections → provider). With a key set, that provider's calls use it directly; without one, calls ride the Glyphh gateway and meter as credits.

Credits & billing

One prepaid currency for everything: model calls, tools, compute. Every charge is itemized per call in your usage feed — never billed in arrears.

How a turn is priced

  • Tokens — each model has an input and output rate in credits per million tokens (shown in the picker's info tip).
  • Prompt cache — cached input bills at a fraction of the input rate (reads 10%, writes 125%), matching what providers charge.
  • On-device models — 0 credits, always.
  • Compute (hosted runs) — metered by wall-clock time.

Plans

Free starts you with 100 credits. Paid tiers add monthly credits, seats, connected services, and cloud sync. Top up any time — manage billing, invoices, and the live usage feed at platform.glyphh.ai.

Stretching credits

Point your loop's worker role at an on-device or open-weight model and save the frontier model for planning — most of an agent session's tokens are worker traffic.

@-mentions & Ghost Mode

Summon a model from anywhere

Type @<provider>-<model> your prompt in any text input — the shell, an app panel, even Gmail's compose box — and press Enter. The text never reaches the app; instead the Ghost overlay opens with a fresh session, that model selected, and your prompt ready to send.

@an-fable ship itFable 5, new session, prompt seeded
@oai-gpt51 summarize this docGPT-5.1
@local-q7 draft a replyQwen 7B on-device — zero credits

Aliases are set per provider and model on the platform's admin Models page. The provider part never contains a hyphen; the model part may.

Ghost Mode

⌘⇧G (Ctrl+Shift+G on Windows) from anywhere — app focused or in the background — floats the agent over the window you're working in, sized to it, on a see-through dark veil. Type, get your answer, and dismiss with Esc or the agent's ×; focus returns to where you were. New workspace panels opened from the ghost land beside the agent, never under it.

Workspace

The workbench tiles live tools next to the agent. Open them from the header toggles or a layout; drag headers to rearrange; drag edges to resize. Arrangements are remembered per working folder, and named layouts remember exactly how you left them.

Tiles

  • Files — the working folder's tree. The search box searches the whole folder (not just what's expanded) — results are click-to-open paths.
  • Editor — a Monaco editor over the tree's files.
  • Terminal — a real shell in the working folder.
  • Diff — what changed, as the agent works.
  • Browser — web preview with an address bar; right-click a page to save it as an app.
  • Plan — the agent's plan files, live.
  • Coding Agent — the agent itself, hostable as a tile in any layout.

Apps beside the agent

Any app from the rail opens as a panel in the workspace. Panels are live — signed-in sessions, notifications, everything — and the agent can read from and act through them.

Apps

Apps live on the left rail. Three kinds: web (any URL, opens as a live panel), native (launches a local application), and glyphh (apps built on the Glyphh runtime — see Build & publish).

Adding your own

Apps page → + New: a slug, a name, and a URL (or a native app path). Org-visible by default so your team gets it too.

Panel commands

Inside any app panel, dot-commands drive the workspace without leaving the keyboard:

@<model> <ask>Summon the agent from any input (see Mentions)
.supCapture the panel's content to the clipboard
.sup ..Capture the agent's last result
.dip <app>Switch panels
.dip layout <name>Open a saved layout
.dripFireworks. You earned it.

The command text is intercepted before the app sees it — nothing leaks into the page.

Marketplace

The Marketplace lists published Glyphh apps — public and your org's own. Installs auto-update by default; pin a version from the app's Releases tab.

Layouts

A layout is a saved arrangement — which tools and apps, in what grid — restorable in one click from the rail, the command palette, or .dip layout <name>.

What a layout can carry

  • Panels + tools — any mix of apps, Files, Editor, Terminal, Diff, Browser, Plan, and the Coding Agent.
  • A loop + its models — opening the layout activates that loop with those model bindings.
  • A target — glyphh (tiles inside the window) or desktop (panels open as positioned OS windows; native apps launch).

Your changes stick

Rearrange or resize inside an open layout and it remembers — reopening brings back exactly what you left, not the original definition. Starting a new agent session never resets an open layout.

Starters

Every account begins with Email (Gmail | Calendar) and Dev (Files/Diff | Editor/Terminal | Coding Agent) as working examples.

Build & publish apps

Glyphh apps are Vite static projects with a glyphh.app.json manifest, built by the agent (or you) in the working folder. The runtime gives them SQLite, on-device vector search, a knowledge graph, cron, your connections, and models — inside a strict sandbox (no external scripts; everything bundles).

The loop

ask the agent"Build me an app that…" — it scaffolds, builds, and installs locally
update_appThe agent reinstalls the working folder's build into your workspace
deployCut a release, upload the source, go live at <slug>.glyphh.app

Releases

The app's Releases tab is the lifecycle: Build & deploy packages the working folder's compiled build, cuts a release, uploads, and deploys; write notes; Promote to live is what installers get. Rolling back is promoting an older release again.

Listing

The Listing tab publishes to the Marketplace: description, media, required connections. Public or org-only.

Connections

Connections give the agent (and your Glyphh apps) authenticated reach into 3,500+ services — Gmail, Slack, Notion, Sheets, calendars, CRMs, and the rest.

Two kinds

  • Org connectors — shared by an admin; members use them without doing their own auth. Governed per workspace, down to individual tools.
  • Personal connections — your own accounts, connected by you, usable only by you.

Manage both under Workspace → Connections on the platform, or from the desktop's Connections page.

Custom MCP connections

Point a connection at any remote MCP server URL — OAuth or headers — and its tools join the agent's toolkit. Custom MCP executes server-side under your org's governance; nothing runs on or dials into your machine.

The CLI

The whole agent, in your terminal — the same engine, loops, models, permission modes, and metering as Desktop.

npm i -g @glyphh-ai/cli
glyphh

Good to know

  • Sign-in is the same device flow, and the session is shared with Desktop (~/.glyphh) — sign in once.
  • /login, /status, /loop, /theme, /help in-session; Shift+Tab cycles the permission mode.
  • Headless and scriptable — drop it in CI, cron, or a Makefile.
  • Install it on a remote box and that machine becomes reachable from your other Glyphh surfaces (machine-reach).

MCP

Glyphh speaks MCP in both directions.

As a client

Add remote MCP servers as custom connections (see Connections) — their tools join the agent's toolkit, executed server-side under org governance.

As a server — drive Glyphh from other tools

External tools (Claude, Cursor, anything MCP-capable) can connect to your workspace at:

https://api.glyphh.ai/mcp

In Claude, add it under Connectors and approve the OAuth prompt. Clients without OAuth use a token via mcp-remote:

{
  "mcpServers": {
    "glyphh": {
      "command": "npx",
      "args": ["-y", "mcp-remote", "https://api.glyphh.ai/mcp",
               "--header", "Authorization: Bearer YOUR_TOKEN"]
    }
  }
}

Connected tools can open your apps and layouts, run your installed apps' tools, call your connections, and build + deploy Glyphh apps. Security model: your desktop holds an outbound connection to the cloud — nothing ever dials into your machine, and only clients you approve get through.
